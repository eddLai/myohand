# One venv for the whole repo: emg/ (Myo armband) and camera/+teleop/
# (MediaPipe teleop). The control stack itself (hand_ctl, hand_set, handd)
# is C and needs none of this.
#
# Must be Python 3.11: libemg needs numpy<2, and numpy<2 has no cp313
# wheel. The combination below is verified working on an Intel Mac.

numpy==1.26.4
pandas
matplotlib

# llvmlite 0.46 起不再提供 macOS x86_64 wheel，會退回從原始碼編 LLVM 然後失敗。
# 鏈路是 libemg -> librosa -> numba -> llvmlite。
llvmlite==0.45.1
numba==0.62.1

# libemg 從 submodule 安裝，而且不能加 -e：
#
#     git submodule update --init
#     pip install ./libemg
#
# 用 -e 的話，從 repo 根目錄執行時 `import libemg` 會解析到 submodule 的外層目錄
# 變成 namespace package（__file__ is None），凡是用到套件相對路徑的功能都會壞。

# mediapipe is pinned, and the upper bound matters as much as the lower.
# The lower one is aarch64: PyPI's newest aarch64 wheel is 0.10.18 and the
# KD240 is aarch64, so 0.10.21 made the board try to build from source and
# die on 1.9 GB of RAM with no swap. The upper one is the API: this range
# used to read <0.11, which pip happily satisfied with 0.10.35 on x86 -
# and 0.10.35 has dropped the legacy `mp.solutions` namespace that
# teleop_app.py uses, so it installs cleanly and then fails at the first
# frame with "module 'mediapipe' has no attribute 'solutions'". Found on
# .112 on 2026-08-06. 0.10.18 is also the version the board was measured
# on (35.8 ms tracking, 27.9 FPS with four threads) and the one
# test_mapping.py checks the mapping against.
mediapipe==0.10.18
opencv-python>=4.10,<5
pysoem
cmake
